## 2. Rules for agents (taken from §1; each one cites the owner's words)

| # | Rule | From the owner's words |
|---|---|---|
| B1 | **There is no catalogue, rack, stock inventory or pre-defined item code.** Each live is unique. Its codes, prices, colours and sizes exist only because the host said them on that live. Codes belong to one live only. | "FORGET ABOUT CATALOGUE, RACKS, STOCK INVENTORY, PRE-DEFINED ITEM CODES … everyday is unique" |
| B2 | **Availability is unknown until store staff confirm it.** Nothing is "in stock" or "sold out" because of a number in the portal. | "we will only find out as checked by the store staff whether available or not" |
| B3 | **Item events come from the host, never from the chat.** An **Item Event** = item code, price, description, colours, sizes, and the time the host called the code. Details the host says before *or* after calling the code belong to that event. | "its the host who will tell those … THJS WAS AGENTS mistake, they find item code from the live chat" |
| B4 | **While capturing an Item Event, do nothing else.** Don't look for buyers or check anything yet. | "DO NOT CHECK, DO NOI START FINDING MINERS OR BUYERS, DO NOT INSPECT ANYTHING YET" |
| B5 | **Order window.** Item N's window runs from Event N's time to Event N+1's time. The last item's window ends when the live ends. Work on window N starts once Event N+1 has been captured. | "In between 1st Event and 2nd Event time stamped … (3rd event - Real work begins)" |
| B6 | **Job 1: 1st capture.** In window N, a buyer comment that contains any of **MINE + code**, **MINE only**, **code only**, or **code + size or colour** is a match. It doesn't have to be an exact match. That buyer's first matching comment is their **1st capture** (buyer + order match) for item N. | "MINE + Item code, MINE only, Item code only, Item code + Size or Colors … doesn't have to be an exact match" |
| B7 | **Job 2: review.** For every 1st capture, review the **entire** live chat **and Messenger**. Count how many times that buyer and order appear. Put each later mention into one of the four types below, and record whether the request was **granted or denied**. | "Reviews the entire live chat … How many times … Was that request granted, or denied? … (Messenger check applies the same)" |
| B8 | **Repeat.** Event → event → jobs, until the live ends. | "3rd Event - (REPEAT THE CYCLE + REAL JOBS) Until the live ends" |

### Job 2 outcomes

| Later mention | If granted | Orders at live end |
|---|---|---|
| Colour, size or item **replacement** | Remove the first order and replace it with what the buyer asked for. This becomes the **2nd capture**. | **1** |
| **Additional order** of the same item (identical, or a different colour or size) | Keep the first order and add the second. This is the **2nd capture plus one**. | **2** |
| **Swap** for another item | Remove the first order and replace it with the other item. This becomes the **2nd capture**. | **1** |
| **Appreciation, side chat or question only** ("Maganda yan", "malambot tela", "magkano") | **Change nothing.** | The 1st capture stands; the comment itself adds no order |
| Any request that was **denied** | Change nothing. | The 1st capture stands |

**Hint, not a rule:** an event usually shows the host holding a garment or several garments.

## 3. Questions waiting for the owner (agents must not guess these)

Each answer will be added to this page with its date.

1. **Who records each Item Event, and when?**
   - Facebook gives the portal the comments, not the host's words, and no replay transcription is connected.
   - Options: (a) a staff member taps code, price, colours and sizes into the portal at the moment the host calls it; (b) an agent takes it from the replay audio after the live; (c) both, with (b) checking (a).
2. **Where does a window end?** When the host *calls* the next code, or when the host *starts showing* the next item? This decides where a "MINE only" belongs if it's posted while item N+1 is being described but its code hasn't been called yet.
3. **Comment delay.** Facebook comments trail the video by a few seconds. If a buyer's "mine" for item N lands just after code N+1 is called, should there be a grace period, and how long?
4. **Granted or denied: how do we know?** Is it the host saying so on the live, a reply in the chat, or a reply in Messenger?
5. **More buyers than pieces.** When store staff confirm fewer pieces than buyers who mined, who gets them: the earliest comment time? The old docs said "first comment wins".
6. **One event with several items.** If the host holds several items with several codes at once, which item does a "MINE only" mean?
7. **Repeated "mine", nothing new asked.** If a buyer repeats "mine" for the same item without asking for another one, is it still 1 order? (Our reading: yes; an additional order needs an explicit request that was granted.)
8. **After the live:** is checking the buying list against what was bought at the store, including the 90% accuracy rule in the old docs, still a step?
9. **"(no order - maybe a buyer previously bought the same item)":** does this mean the appreciation comment adds no order, and the buyer's earlier order for that item, if any, stays as it is?
